## 已定位并挂载运行补丁

旧 Scheduler 将官网目录请求、到期任务派发/租约恢复、通知投递、心跳放在同一循环。实际运行中见到 Scheduler 心跳过期后恢复，慢目录请求会拖延其他步骤。现已拆分目录、派发/通知、心跳三个异步循环，两个网络循环各用独立 HTTP 连接池，避免配置刷新关闭另一循环正在使用的连接。取消时共同等待退出，再释放资源。

新增回归用挂起的目录请求和 Telegram 请求分别证明另外的循环与心跳继续工作，且退出时两个池各关闭一次。连同派发公平性、价格管线、集团健康和运行配置等相关测试共98项通过。
