# 批量日历监控（2026-10-15，本地未发布）

启用“全球酒店自动轮询”和万豪采集，并在页面采纳已经成功读取的万豪中文官网目录，
Scheduler 就会自动为该来源下的启用酒店安排月历任务，无需逐酒店手工填写。
每家酒店依次轮换未来365天涉及的12或13个自然月，首尾月份按日期窗口裁剪。
时间统一使用 Asia/Shanghai。任务、月份游标和候选保存在数据库中，重启后继续。

官网日历起价保存到独立历史，酒店页面日期格可查看金额、币种和采集时间。
“未来一年价格采集进度”分别统计日历观察和具体房型查询；同一酒店同一天的重复
观察只计一个日期，旧记录达到刷新间隔后显示过期。起价没有证明税费和会员条件。
当前月历通道仅支持万豪中文来源，其他五集团继续使用已有的官网单晚适配器。

默认至少有3个不同历史日，当前起价低于历史每日中位数50%才生成候选。
随后自动查询该日期的公开非会员含税房型，并在默认60秒后独立复查同一房型方案。
两次真实房型总价都满足降价阈值，才建立 Telegram 待发送记录；消息包含酒店名、
集团、入住／退房日期、币种、金额及比较基准。历史天数、降幅和复查间隔使用现有设置。
再次提醒还须满足额外降价比例。队列满时保留候选，来源变更或住宿过期时取消候选。

自动全球扫描采用已支持的月历通道，避免同时为万豪补出365个逐日首次查询任务。
用户明确关注和手动查询仍走具体房型；此前已经建立的日期任务继续按正常规则处理。
全球目录数量和全年日期覆盖仍取决于实际成功读取的数据。
