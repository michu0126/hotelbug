# 官网会话连接

在页面的“官网会话连接”中选择集团、填写 Cookie 所属官网，再粘贴 Cookie 并保存。
API 与采集容器沿用现有共享浏览器数据卷，不增加 Compose 服务、端口或环境变量。

## 输入格式

- 单行请求头：`session_name=示例值; another_name=示例值`，也可带 `Cookie:` 前缀。
- JSON：浏览器导出的 Cookie 数组，或包含 `cookies` 数组的对象。
- Netscape：粘贴文件内容，支持 `#HttpOnly_` 与会话 Cookie。

请求头不含域、路径和过期信息，所以严格使用填写的官网主机；推荐 JSON，以保留这些属性。
例如万豪英文官网填写 `https://www.marriott.com`，中文官网填写
`https://www.marriott.com.cn`。两者 Cookie 不互通，连接器不会擅自替换当前目录来源。
JSON 内只能包含所选集团官方域 Cookie；不接收其他网站或第三方登录系统的 Cookie。

## 使用与验证

1. 上方填写现有管理令牌，点击“读取连接状态”。
2. 保存后显示“已保存 · 尚未验证报价”，不冒充登录成功。
3. 在已收录酒店中选择该集团酒店，选择未来一年内入住日，点击“测试实际报价”。
4. 后台使用正常队列执行一晚、一间房、两名成人的采价任务。
5. 读取状态可看到任务状态与实际入库报价条数；价格和会员条件仍在酒店日历／历史中查看。

真实报价测试不触发降价提醒。保存新 Cookie 后，旧版本的待执行测试会被取消，需重新提交。
集团启用设置、官网暂停、请求间隔、正常报价校验不被绕过。
测试成功且零条报价可能是官网确认无房或尚未开放预订，不能当成零元房。

采集端在下一新页面应用配置。存在同集团正在执行的浏览器任务时，会等待任务结束，
不替换该请求进行中的账号会话。保存后无需重建容器；页面新增功能本身仍需要更新发布版本。
清除配置只移除已导入的对应 Cookie，不删除整个浏览器资料或酒店／价格历史。

## 保存范围

Cookie 值只保存在浏览器数据卷的 `.connections/<provider>.json`，Linux 目录权限700、
文件权限600；与普通浏览器资料一样属于本地凭据，并非加密备份。
不把 Cookie 放入数据库设置、任务负载、API响应、前端持久存储或镜像。
NAS管理员仍可读取数据卷，因此备份需按凭据文件保护。只通过可信内网或HTTPS填写。
页面只显示未过期数量、保存时间、最早持久Cookie到期时间与测试任务状态。
最早Cookie到期时间不代表账号登录有效期；会话Cookie没有可预知的过期时间。

## 2026-10-17万豪官网现场观察

正常在Chrome操作官网，南京、2026-11-12入住／11-13退房、一间房、两名成人、现金普通价。
观察到官网实际POST：

- `/mi/query/phoenixShopDatedSearchByGeoQuery`：按地理范围返回多个酒店的最低可售报价。
- `/mi/query/PhoenixBookDTTSearchProductsByProperty`：指定 `propertyId` 返回房型／产品数据。

二者都位于 `https://www.marriott.com`。实际响应无GraphQL错误；南京玄武湖威斯汀的
`propertyId` 是 `NKGWI`。请求包含 `startDate`、`endDate`、`quantity`、`numberInParty`。
将成人数从2改为1后，正常官网新请求中的 `numberInParty` 确认变为1。

列表请求的 `includeTaxesAndFees=false`，不能将展示的699元当作含税总价。
本次响应的 `lowestAverageRate.amount` 为69900、币种CNY、`decimalPoint=2`，
对应699元；`totalAmount` 为81503，即815.03元。房型页面勾选
“Show with taxes and fees”后显示815 CNY／Night，并明确标记税费已包含。
此例是单晚，两晚或多晚还需另行验证总额／均价口径，不能直接类推。

这是已观察到的官网页面请求，不是承诺可供所有NAS无限直接调用的公开API。
当前连接器为现有浏览器采集器导入Cookie，没有把上述GraphQL接口硬编码为独立HTTP采集器，
也没有证明“仅复制Cookie即可在任意设备长期请求”。账号价、积分价、退款及早餐条件继续分开校验。

## 验证

包含格式／域隔离／过期／凭据不回显、认证管理API、队列与实际报价入库、
旧测试取消、无通知、同一浏览器资料更新／清除的离线测试。
发布流水线额外在真实Linux Chromium验证Cookie导入、同资料更新和清除；不访问酒店网站。
Windows本机独立Chromium启动报 `spawn UNKNOWN`，未以更换用户Chrome资料或忽略安全校验替代。
最终容器浏览器验证以发布流水线实际结果为准。
