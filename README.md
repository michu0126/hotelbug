# Hotel Bug Price Monitor

自托管酒店价格情报平台，目标部署环境为群晖/Linux/Docker。雅高与 GHA 已通过官网页面的真实任务测试；六集团全球覆盖仍在开发。

## 当前交付与边界

- Python 3.12+ / FastAPI / SQLAlchemy / Alembic / PostgreSQL / Redis。
- 六服务 Compose、独立 Scheduler 与 Worker、持久化任务、优先级、去重、租约恢复、独立 Provider 限流。
- 标准化 Hotel/Rate 数据结构、Decimal 金额、追加式历史、报价身份隔离，并记录每次成功查询的有房/无房状态。

## 新版部署

Intel/AMD x86_64 群晖；当前只构建 amd64，ARM64尚未验证。独立 `worker` 构建目标包含 Chromium 与内置虚拟显示器，API和Scheduler镜像不安装浏览器。显示器仅容器内部使用，无需额外端口或用户桌面连接。浏览器采集建议 NAS 至少预留2GB内存，实际消耗以部署监测为准。

```bash
git clone https://github.com/michu0126/hotelbug.git
cd hotelbug
cp .env.example .env  # 仅首次安装；升级时保留已有 .env 并补充新变量
docker compose pull
docker compose up -d
```

首次部署前编辑 .env：
- POSTGRES_PASSWORD：改成随机的URL安全字符串（例如32字节随机十六进制）；不要在已有数据库上只改密码变量而不修改数据库角色密码。
- ADMIN_TOKEN：管理写入认证；留空时写入返回503，只读状态仍可用。
- WEB_PORT：默认8098；与仍在运行的旧版并行请改8099。

访问 `http://NAS-IP:8098`。只前端端口对宿主开放，PostgreSQL/Redis不映射宿主端口。
这是内网部署；公网访问需要带认证和TLS的反向代理。没有把登录界面冒充完整权限系统。

Compose 会按依赖健康顺序启动数据库、迁移/API、Worker、Scheduler、前端。根目录 Compose 使用镜像发布标签；部署前确认对应 CI 已成功发布。源码构建需在完整仓库目录中额外使用 `docker/compose.build.yml`：

```bash
docker compose -f docker-compose.yml -f docker/compose.build.yml up -d --build
```

本地未发布优化：同酒店、入住/离店、成人数与房间数的多条降价候选共用一次独立复查请求，不再每个方案重复打开整张官网报价页。历史基准和复查判定仍逐房型/方案进行；恢复正常价或复查消失的方案不会通知，其他仍低价的方案可各自通知。兼容原先单条候选的待办复查任务。该优化的本地测试不代表真实机器人或六集团全量验收已通过。

全球轮询新增失败日期补采：首次采价因TIMEOUT、NETWORK_ERROR、RATE_LIMITED或浏览器临时启动错误而重试耗尽的单晚日期，不必等全年游标绕回。按现有HOT/WARM/COLD周期重新排正常采价任务，保留旧失败记录，不伪造StayScan或报价。只补最新失败且尚无成功观察的默认2成人/1房日期；已有成功记录走原复查通道。活跃任务、更新尝试、集团暂停、Retry-After、非一年范围及队列容量均抑制重复；解析/安装/明确权限拒绝等错误不在此盲目重放。补采与已知日期复查共享原复查名额并轮换，全年新日期推进仍保留名额，游标写入数据库可重启续跑。

减少重复健康测试：集团ONLINE且近一小时已有真正成功的价格查询/无房/未开放预订记录时，不再额外请求固定测试酒店。心跳、目录读取、单独ONLINE标记和失败/过期/未来记录不作为采价证据；集团暂停时不新增检查。自动健康任务已有活跃实例时不重复创建；已排队的自动检查若执行前出现新成功记录，则取消这个冗余检查。用户显式提交的健康检查仍执行，正常监控价格轮询不受影响。无近期采价证据或状态退化时恢复原低频检查，不新增必需环境变量或数据库迁移。

本地降价基线修正：从拥有足够独立历史观察日的窗口中按30→7→90天选择每日中位数，避免一律使用旧90天报价；不足最少天数不触发提醒。7/30/90天统计各自保存，全部历史最低/最高保存实际观察金额，不用每日中位数代替。明确会员价或未确认房型/方案的汇总价不用于公开低价通知。

同条件已有确认价后，默认只有较最近确认价再下降至少20%才创建新候选；例如确认70后，56或更低可以再次提醒，60不能。此比例可在页面修改，且独立复查后的价格也必须满足该条件。正在等待/重试的复查不叠加新候选；复查拒绝或终止后，下一次正常采价仍可重新发现候选，不再锁死到第二天。一个任务重复返回同报价身份只处理首次观察，与历史入库规则一致。

复查任务失败、取消或Worker租约重试耗尽后，Scheduler分批收敛旧候选状态，页面不再永久显示“待复查”。失败显示标准错误代码，取消可显示集团已关闭或日期超出范围；不复制原始错误文本到公开提醒。正常有界重试仍显示待复查；确认前不产生通知，已确认/已拒绝结果不会被修复流程覆盖。以上改动通过相关109项离线测试与本地浏览器页面核对，不是新增官网实采或真实Telegram送达证明。

本地新增历史新低独立提醒与可配置异常评分：新低默认开启，可在页面关闭；同条件当前报价低于此前全部历史最低时进行独立复查。最低本身和“可能Bug价”不是同一概念，普通新低会明确显示为普通等级。与大幅降价同时发生只生成一份候选/复查/通知；仍遵守最近确认价后重大额外下降的去重规则。没有近90天中位数时，若全部历史已有足够独立观察日，可用此前历史最低作为明确标注的新低参考，不捏造近期中位数。

- POST /api/jobs（同认证，万豪 DISCOVER_HOTELS 可用 `payload.provider_hotel_id` 指定五位代码）
- POST /api/hotels/{id}/calendar/jobs?month=2026-10（同认证，为未来365天范围内该月逐日生成任务）
- GET /api/watchlists?limit=100&offset=0（分页，limit最多200）
- POST /api/watchlists（需管理令牌；单酒店兼容 `{"hotel_id":"...","days_ahead":30}`；宽范围例如 `{"scope":"country","country":"CN","days_ahead":365}` 或 `{"scope":"provider","provider":"ihg","days_ahead":365}`；城市/品牌用对应 `city`/`brand` 字段，可附加 `provider` 限定集团。同目标保存更新并恢复启用，不重置日期进度）
- PATCH /api/watchlists/{id}（需管理令牌；`{"enabled":false}` 暂停新增任务，true恢复）

## 备份与恢复

在NAS的shell中将数据库导出到用户选择的备份目录，并同时安全备份.env：

```bash
docker compose exec -T postgres pg_dump -U hotelbug -d hotelbug -Fc > hotelbug.dump
```

恢复到**全新、空的数据库卷**，先仅启动postgres，数据库存在后导入，再启动其他服务：

```bash
docker compose up -d postgres
docker compose exec -T postgres pg_restore -U hotelbug -d hotelbug --no-owner < hotelbug.dump
docker compose up -d
```

不要对有数据的现有库直接恢复，避免重复或覆盖。Redis是队列投影，可以由PG到期任务恢复；通知与历史事实在PG中。
/data、/logs使用命名卷；业务结构化日志输出stdout，Docker每容器10MB×3轮转。
日志禁止记录Authorization、完整Cookie、密码和会话；默认不持久化原始响应。
